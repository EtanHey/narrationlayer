# Narration contract verification
Status: local slice for lead-routed review; I01-I10 design-level; real-code binding required in each implementing PR.

Run `formal/narration-contract/check.sh`. Existing Bun, Python 3 and `~/.local/bin/tlc` are required. TLC is tla2tools 1.7.4 (banner: TLC2 2.19, revision 5a47802); the runner caps each JVM at 512 MiB and one active CPU. No dependency download occurs. Each invocation prints a new scratch artifact directory and retains complete TLC output/configs, actual-source observations and a hash-bound summary. A failed run retains its artifacts too.

The source-backed promise is small: after an awaited single-writer publication, DONE and FAILED must not coexist. Conflicting markers mislead callers about success. `src/job-store.ts:170-179` removes the opposite marker before writing its own. `source-probe.ts` executes those real exports from a byte copy, with public job IDs and temporary directories. SourceTrace checks observations after each call; it does not treat the two filesystem operations as atomic or prove concurrency safety. Removing each unlink must break the same invariant; restoration must pass. No render is invoked.

`NarrationContract.tla` models the proposed four domains and external admission from accepted v5 `STATE-CONTRACT-CASES.md`. `coverage.json` maps I01-I10, actions, bounds and omissions. Every invariant has a deliberately broken model variant. These mutants establish model sensitivity only; they do not establish real engine coupling. The existing source contains no shared reducer/lease/eligibility/admission implementation. No speculative engine is added to conceal that gap.

Bounds: one focal job chosen from two job identities; two serial owner/attempt pairs, two controls/player IDs, two chunks, one aggregate lease/write and one matching versus mismatching media token. Feedback enumerates foreign job/owner/attempt tuples only. Same-session control/player feedback races are not covered; old and new players never coexist. This is a reduced identity-race model, not two concurrent job state machines. There are no queue/deadline bounds because queues and deadlines are omitted. Model Step boundaries are proposed reducer transactions; they are not asserted to be atomic in current code. Late old-player cleanup is separate from lifecycle feedback.

Safety has no fairness assumptions. Explicitly disabling deadlock checking permits terminal, paused and unknown-backend quiescence; no internal-deadlock claim follows. `DrainProgress.tla` separately proves eventual safe under weak fairness for close, backend exit and safe declaration, assuming a responsive backend and no other work/leases. Its unresponsive safety check passes; a separate progress check must fail with exit 13, demonstrating that no progress guarantee follows for an unresponsive backend. It does not establish full-contract liveness or guarantee backend termination, user resume or successful persistence.

Counterexamples use code nouns: foreign-feedback accepts a foreign job/owner/attempt EOF; lease-delete unlinks held bytes; abort-drain falsely treats client abort as backend exit; seek-pause loses pause while reaping; timing-identity accepts mismatching media; reject-reuse selects after rejection; reopen-terminal reopens cancellation; late-commit publishes after cancellation; truncated-eof completes after one chunk; archive-prerequisite archives before the genuine playing write. Each must fail its named invariant (all others remain enabled). Read `*/tlc.out` for shortest BFS paths.

`C21-witness/tlc.out` must violate **NoLateFailure**: generate both chunks, start playback, seal, receive natural EOF, then fail final publication. Playback stays completed while generation becomes failed; this is required behavior. C14 is represented by withholding PersistPlaying after actual start/EOF: pending retention blocks archive/release until the genuine playing write succeeds. Unknown backend and player status remain deferred; there is no no-child-proof recovery action. Full route-specific History behavior and crash intent recovery are explicitly uncovered.

Source drift is a hard stop, not proof of a bug. Inspect the change, update mapping and coupling before advancing the sync commit/hash. A new invariant failure requires checking the model against the contract and reproducing against real code before claiming a product bug. Preserve unexpected failures. See the project-local `verify-narration-contract` skill and pstack `/statechart` and `/maintain-formal-verification-skill`.

Model limits: pause/resume commands during restart are omitted. Successor shares one aggregate artifact and can start only while it exists; eligibility/timing are reset per attempt. BackendExit combines physical exit and observation; Spawn checks capture/admission atomically. Crash retains volatile flags. `receipts.json` is the last observed run, not an automatic golden baseline. Python gates use explicit exits and isolated mode, unaffected by optimization. Unresponsive progress must fail with TLC exit 13.

Each implementing PR named in coverage.json must bind its invariant to real behavior or an implementation-derived trace, record source hashes/sync commit and a failing real-source scratch mutation plus restored pass. This design slice does not waive those gates.
